Climbing Stairs

1 段または 2 段ずつ上る階段で、頂上までの上り方を数える問題です。動的計画法の考え方を、文章を中心に説明します。

1. 問題の整理

入力は頂上までの段数 n です。1 回の移動では 1 段または 2 段を上れます。n 段目に着くまでの、異なる上り方の数を返します。

n は最大 45 なので答えは int に収まります。なお、上り方の順序は区別します。たとえば 3 段の場合、1 + 2 と 2 + 1 は別々の方法です。

2. 素直に数えると何が起きるか

各地点で「1 段上る」「2 段上る」と分岐する再帰を考えることはできます。しかし、4 段目への方法を求めるとき、3 段目や 2 段目への方法を複数回求めることになります。同じ計算の繰り返しが、再帰だけで解く方法を非効率にします。

3. 最後の一歩から漸化式を作る

ways[i] を「i 段目に到達する方法の数」とします。i 段目へ最後に 1 段上って到着したなら、その直前は i - 1 段目です。最後に 2 段上ったなら、その直前は i - 2 段目です。

この二つのグループは重ならず、すべての到着方法を含みます。そのため、それぞれの方法数を足せば答えになります。

4. 実装の流れ

配列にすべての ways[i] を保存することもできます。ただし、次の値を求めるのに必要なのは直前の二つだけです。そこで、1 段目の値 1 と 2 段目の値 2 を二つの変数に保持します。

更新では、まず next を計算することが大切です。previous を先に更新すると、和を作るための古い値を失ってしまいます。

int previous = 1; int current = 2; for (int step = 3; step <= n; step++) { int next = previous + current; previous = current; current = next; }

5. 具体例: n = 5 を追う

初期状態は、1 段目に到着する方法数が 1、2 段目に到着する方法数が 2 です。3 段目では 1 + 2 = 3、4 段目では 2 + 3 = 5、5 段目では 3 + 5 = 8 と計算します。

下の図では段数を変えたり、「次を計算」を押したりして、変数がどのように入れ替わるかを確認できます。これは上の説明を補うための操作例です。

5
previous = ways[i − 2]—2 段前
current = ways[i − 1]—1 段前
next = previous + current—次の値

6. 計算量

3 段目から n 段目まで一回ずつ計算するため、時間計算量は O(n) です。保持するのは previous、current、next の三つだけなので、空間計算量は O(1) です。

O(n)支配的な処理は n − 2 回のループです。
O(1)段数にかかわらず、一定数の整数変数だけを使います。

7. つまずきやすいポイント

  • n = 1 と n = 2 は先に処理します。初期値とループ範囲が明快になります。
  • 和を保存する変数を用意してから、previous と current を更新します。
  • 上り方の順序が異なれば別の方法です。
