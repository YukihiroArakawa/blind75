LEETCODE 322 · DYNAMIC PROGRAMMING

Coin Change

金額ごとの「最小硬貨枚数」を小さい金額から確定していく、ボトムアップ動的計画法の問題です。

1. 問題の整理

coins は使える硬貨の額面、amount は作りたい金額です。各額面は何回でも使えます。金額を作れる組み合わせのうち、硬貨の枚数が最も少ないものを求めます。作れなければ -1 です。

ここで求めるのは組み合わせの数ではありません。5 + 5 + 1 のような作り方の中から、使った硬貨の枚数が最小のものを一つ選び、その枚数だけを返します。硬貨を並べる順序も結果には影響しません。

2. 素直に考えるとどうなるか

金額を残り額として考え、使える硬貨を一枚ずつ試す再帰は思いつきやすい方法です。たとえば残り 11 に対し 5 を選べば、次は残り 6 を解きます。さらに 1 や 2 も選べるため、選択肢ごとに再帰が枝分かれします。

しかし、同じ残り額を何度も計算します。11 から 5 を使った経路でも、8 から 2 を使った経路でも、途中で「残り 6 を作る最小枚数」が必要になります。再帰だけでは、この答えを毎回作り直すことになります。

この重複を避けるため、各金額の答えを一度だけ記録し、次の金額の計算で再利用します。これがこの問題で動的計画法を使う理由です。

3. 採用するアプローチ

minimumCoins[x] を「金額 x を作る最小硬貨枚数」とします。金額 x の最後に額面 coin を使うなら、その前には x - coin を作っています。したがって、その最小枚数に 1 を足せば候補になります。

たとえば coins = [1, 2, 5] で金額 6 を考えます。最後の硬貨を 1 にするなら minimumCoins[5] + 1、2 にするなら minimumCoins[4] + 1、5 にするなら minimumCoins[1] + 1 が候補です。この中で最も小さい値を選べば、6 を作る最小枚数になります。

minimumCoins[x] = min(minimumCoins[x - coin] + 1)

金額は小さい順に計算します。すると minimumCoins[x] を求める時点で、必要な x - coin は必ずすでに計算済みです。

未到達の金額は amount + 1 で初期化します。硬貨はすべて正の整数なので、金額を作れる場合に必要な硬貨枚数は最大でも amount 枚です。よって amount + 1 は答えにならず、「まだ作れない」という印として安全に使えます。

4. 全体の流れとコードの読み解き

まず金額 0 の最小枚数を 0 にします。これは「何も使わずに 0 を作れる」ためです。続いて 1 から amount まで順に、各硬貨を最後の一枚として試します。より少ない候補が見つかったときだけ値を更新します。

外側のループは「いま最小枚数を決めたい金額」を表します。内側のループは「その金額に最後に置く硬貨の候補」を表します。coin <= currentAmount の確認は、硬貨が現在の金額より大きく、前の金額が負になるケースを除くために必要です。

for (int currentAmount = 1; currentAmount <= amount; currentAmount++) { for (int coin : coins) { if (coin <= currentAmount) { minimumCoins[currentAmount] = Math.min( minimumCoins[currentAmount], minimumCoins[currentAmount - coin] + 1 ); } } }

配列にはすでに最小値が入っているため、候補を上書きするのではなく min で比較します。最後に minimumCoins[amount] が未到達のままなら -1、そうでなければその値を返します。

5. 具体例: coins = [1, 2, 5], amount = 11

0 から順に最小枚数を作ります。金額 5 では硬貨 5 を使う候補が 1 枚となります。金額 10 では 5 に硬貨 5 を足して 2 枚、金額 11 では 10 に硬貨 1 を足して 3 枚です。

金額 6 では、硬貨 1・2・5 のすべてを最後の一枚として試します。候補はそれぞれ minimumCoins[5] + 1 = 2、minimumCoins[4] + 1 = 3、minimumCoins[1] + 1 = 2 です。このように、候補を比較した結果だけを配列に残します。

6. 計算量

金額ごとにすべての硬貨を一度ずつ試します。金額の数は amount + 1、硬貨の種類数は coins.length です。硬貨の額面そのものが大きくても、ループ回数は額面の値には直接依存しません。

O(amount × coins.length)各金額について、各額面を一度ずつ確認します。
O(amount)金額ごとの最小枚数を配列に保存します。

7. つまずきやすいポイント

  • amount = 0 の答えは 0 です。硬貨を使わずに作れます。
  • 到達不能を 0 で初期化すると、最小値の比較が壊れます。答えより大きい値を印に使います。
  • coin > currentAmount の場合、currentAmount - coin は負になるため候補にできません。
  • 貪欲に大きい硬貨から使うだけでは常に最適とは限りません。例えば coins = [1, 3, 4]、amount = 6 では 4+1+1 より 3+3 が少ない枚数です。すべての硬貨候補を比較する動的計画法なら、この違いを正しく扱えます。
